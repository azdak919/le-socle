## Git

La source de vérité, quand le clone est sous `VisualCode/`, est `../GIT-AND-TEST-SAFETY.md`.

- Branche, vérification locale, pull request, lien cliquable. Pas de commit direct sur `main`.
- Identité des commits : **Azdak** `<azdak-qc@proton.me>`. Jamais d'autre nom ni d'autre courriel.
- Pour se mettre à jour : fusionner `main` dans la branche. Pas de force-push, pas de réécriture d'un historique déjà poussé.
- Fusion : une pull request se fusionne quand le job `test` est vert, avec l'accord du propriétaire, en squash, branche supprimée. Un agent ne fusionne que si le propriétaire l'a autorisé, lui-même, pour ce travail. Jamais sur une CI rouge ou en attente.
- Vérification locale avant push : `npm test`.
- Admin de rédaction : elle se développe ici, sous `admin/`, et nulle part ailleurs. JavaScript simple (pas de TypeScript), car le Kiosque l'importe depuis `node_modules`. Chaque fichier de `admin/assets/` figure dans `ADMIN_ASSETS` (`admin/page.js`) ; ceux du mode serveur dans `SERVER_ASSETS` (`src/redaction-page.ts`) et dans `SOCLE_REDACTION_ASSETS` (PHP). PGlite n'est jamais servi par le socle : il n'existe qu'en mode navigateur. Après un changement de `admin/page.js` ou de `admin/ui/`, lancer `npm run ui` et versionner `admin/assets/admin.css` et `admin/serveur.html`.
- Workflow : `.github/workflows/verification.yml`, nom **Vérification**, job **`test`**.
- Sous `/v1/`, `GET /v1/health` est la seule route tant que les modules sont éteints. `GET /v1/editorial/snapshot` n'existe que si `editorial` est allumé. `/v1/auth` n'existe que si `auth` est allumé. `POST /v1/review/echeance` n'existe que si `review` est allumé : elle publie les articles dont l'heure est passée, sans réécrire le site statique. `POST /v1/audience/event` n'existe que si `audience` est allumé. Le compte est une somme, datée au jour civil de Toronto. Pas d'adresse, pas d'identifiant de personne. Le détail tient 90 jours, puis une ligne de semaine. Le poids sportif n'est pas allumé. Les noms d'événements ne sont pas dans `socle.config.json`. `POST /v1/notify/abonnement` n'existe que si `notify` est allumé. Le retrait se fait par un lien. Le courriel part par le SMTP du projet. Le push est signé par des clés que le projet génère, pas par un service tiers. L'adresse est dans l'archive du journal, pas dans `index.html`. La clé privée n'est ni dans l'archive, ni dans `socle.config.json`. Le mode, le SMTP, le client GitHub et l'adresse du responsable ne sont pas dans `socle.config.json`. Le bouton de mise à jour reste ouvert tant que `auth` est éteint ; allumé, il est réservé au responsable. La décision de relecture est au réviseur, à l'éditeur ou au responsable quand `auth` est allumé. `/admin` sert la sauvegarde, la mise à jour, les articles, la relecture, la file des crédits manquants, les totaux d'audience et les abonnements, chacun seulement si son module est allumé. Les modules restent éteints dans `socle.config.json`. `/v1/redaction/` n'existe que si `editorial` est allumé : c'est l'API JSON de l'admin du Kiosque (état, article, entité, suppression, publication, exemples, et la banque de photos `photo`, `photo/fiche`, `photo/supprimer` si `media` est allumé). Sans `auth`, elle ne répond qu'à la machine du socle, et un en-tête de mandataire (`X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `CF-Connecting-IP`) suffit à refuser. Avec `auth`, un rôle est exigé ; publier, programmer, archiver, supprimer et gérer sections, catégories et étiquettes demandent un réviseur, un éditeur ou le responsable. Les écritures n'acceptent que `application/json`. Une photo de banque exige un crédit, est reniflée par ses octets (JPEG, PNG, WebP, 8 Mo au plus) et ne se retire pas tant qu'un article l'utilise. Le socle sert lui-même l'admin de rédaction sous `/redaction/` (page `admin/serveur.html`, fichiers `admin/assets/`) quand `editorial` est allumé, en Node comme en PHP, avec les mêmes octets. `SOCLE_STATIC` sert le site construit, à la même origine ; Node suit les mêmes règles que PHP (pas de `..`, pas de lien qui sort de la racine). La même suite passe sur SQLite, PGlite, D1, le serveur Node et PHP.
